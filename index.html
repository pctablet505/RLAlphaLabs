The Test, Closer

Why “Almost a Tie”
Is the Honest Answer

Pooled over all 1,154 forecasts, the AI model leads by 1.4 points. Quarter by quarter, the lead flips.

Quarter by quarter, the winner kept changing

In two of the five quarters the AI model was ahead; in three it was behind. Swings this big from one quarter to the next are why we do not trust a 1.4-point lead.

How far ahead could it really be?

Our estimate of its lead is 1.4 points. The plausible range runs from 4.9 points behind to 7.7 points ahead. We required 10 points ahead. Even the generous end falls short.

Written first

The design was fingerprinted before the first request to the model.

Read once

We read the result once, on quarters the design held out. No second try.

Hindsight on its side

The model was trained after these results came out. That could only help it.

Spot a flaw in this test? We want to hear it.

Six Results
That Surprised Us

Read each question and pick a guess. Our answer follows a moment later, whether you pick or not.

Your guess?

A stock is announced for addition to a major index. Does it rise after the news?

Before, not after.

In our tests the rise came before the announcement, not after it. After costs, our estimate of buying on the news was below zero.

Your guess?

Commodity price shocks predicted company results. Could you make money buying on them?

No. It lost money, even before costs.

The shocks did predict reported results. Predicting the news and profiting from it are different things.

Your guess?

A data pipeline quietly dropped 16 index members it could not match to an identifier. Harmless?

Not one survivor.

All 16 had merged, been renamed or wound up. Leaving out the companies that failed makes a backtest look better than the truth.

Your guess?

A test’s smallest detectable effect is set at two standard errors. If the true effect is exactly that big, how often does the test find it?

About half the time.

Two standard errors is the pass mark, not the power. Our designs now state the effect they can detect 80% of the time.

Your guess?

A code-quality gate counted 304 fewer errors and recorded an improvement. How many were real fixes?

None.

A setting the tool silently ignored made the count depend on the shell, not the code. Now a falling count is suspect until explained.

Your guess?

One of our AI agents reported there was no intraday data on disk. Was there?

Years of it.

The agent had checked one empty table; the minute data sat in another store. Now every claim, even “there is none”, is read from where the thing actually lives.

How We Test

From Idea to Verdict,
Five Steps We Do Not Skip

Every step is here because skipping it once fooled us. The traps below show how.

1
A written question

One idea, one bar to beat

Each idea starts as a question, with the bar it must beat: usually an index fund or a simpler method, after real costs and tax.

2
Frozen first

Fingerprint the design before any result

A study’s design, data and code are fingerprinted before the first result is read, so a result cannot be tuned after the fact.

3
Real costs

Count every cost

Securities transaction tax, stamp duty, exchange charges, GST and the spread we would actually pay. Measured on the live order book rather than guessed.

4
One read

Test on data it was not fitted to

We look for effects that survive real trading costs and tests on data they were not fitted to. A frozen test is read once.

5
On record

Record the verdict, whichever way it goes

Pass or fail, the verdict is written down with its reason. We do not re-run a frozen test to get a different answer.

Backtest Traps

Five More Traps
That Fooled Us, Or Nearly Did

A backtest reports how an idea would have done. Its worst errors do not crash. They return a number that looks reasonable, and usually better than the truth. Three of the traps are in the guesses above; here are five more.

Trading at the price you decided on

One comparison said spreading an order through the day cost far more than buying at the close. But the test decided on the closing price and filled at that same close, which no live order can do. Filled a day later, as a real order would be, the difference disappeared.

Now Fills come at least one session after the decision, and every report shows how far the result moves between the two.

Testing only the companies that survived

If the stock list holds only companies still trading today, every company that failed is missing from the past. We measured the inflation at roughly 2.4 to 4.2 percentage points a year, larger for longer lists. A later cross-check has not yet reconciled the exact size, so we treat it as an estimate.

Now Lists are built as they stood on each date, and an edge smaller than this bias counts as unproven.

Prices of zero at the start of history

To find where a stock’s history begins, a probe asked whether the data source returned any rows for a date. For one stock it returned months of rows with every price at zero, and the history appeared to start there. A zero next to a real price also looks like a crash.

Now A row counts as data only if its prices are valid, and start dates found the old way are suspect until recomputed.

A control that cannot fail

A negative control scrambles the data so that no real effect can survive. Ours returned the real run’s number to the last digit, and the check read “pass”. It happened twice in one day, through two different bugs, and nothing raised an error.

Now Every control’s score is compared with the real run’s, and identical digits stop the run.

A language model that already knows the answer

A model trained on text that covers the test years may have seen the outcomes. We tried to measure that with other language models, but they share the same hindsight, and no check run with them can prove it absent.

Now We read such backtests one way only. A fail is a real negative; a pass is at best an upper bound. The clean test is forecasting results that have not happened yet.

AI-Native Lab

One Person, a Team of AI Agents,
and a Rulebook

RL Alpha Labs has one founder. AI agents from several vendors draft most of the plans, code, tests and reviews, under one written rulebook, and a change is reviewed by an agent that did not write it. That works only if software enforces the rules.

Guards that refuse

Automated guards check commands before they run and refuse the dangerous ones, such as rewriting history, deleting data or reading a file that holds a secret. A refusal names the safe route.

Every claim read from its source

A number in a report is read from the file or command that produced it, never quoted from memory.

Every fix ships a test that fails first

The test must fail on the old code and pass on the new. A check is also shown failing on a planted defect, because a check that cannot fail proves nothing.

Agents never trade, never touch credentials

No agent can place an order or read a key, token or password. A person decides at every gate.

What went wrong, and the rule it left

An agent once restored four result files with a command that empties its target before it runs. The files had never been saved to version control, so all four ended up empty.

Rule Commands that can destroy work are refused, and a restore must start from a file that history really holds.

An agent once edited code while a test run was still reading it. The third run counted 57 fewer tests than the first two, and nothing in the output said why.

Rule Tests run through one shared scheduler, on a copy of the code that nobody edits while it is measured.

Two more incidents, and the rules they left, are in the note: how one person runs a lab with AI agents →

The rules slow some work down. A fix takes longer when it needs a failing test first, and a study waits until its design is frozen. We accept that: a fast wrong answer costs more than a slow right one.
