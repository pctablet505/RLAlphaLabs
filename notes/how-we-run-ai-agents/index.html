How One Person Runs a Lab
with AI Agents

Updated October 2026

RL Alpha Labs has one founder. AI agents draft most of the plans, code, tests and reviews. That works only if the agents follow rules a careful person would, and if software enforces the rules.

The principles

  • Several models, several vendors. Models from different vendors work side by side, and a change is reviewed by an agent that did not write it. No single vendor is central.
  • One written rulebook. Every agent reads the same rulebook, whatever its vendor, and each rule keeps a record of the evidence behind it.
  • Guards that refuse. Automated guards check commands before they run and refuse the dangerous ones, such as rewriting history, deleting data or reading a file that holds a secret. A refusal names the safe route.
  • Every claim read from its source. A number in a report is read from the file or command that produced it, never quoted from memory.
  • Every fix ships a test that fails first. The test must fail on the old code and pass on the new. A check is also shown failing on a planted defect, because a check that cannot fail proves nothing.
  • Designs are fingerprinted before data is read. A study’s design, data and code are frozen and fingerprinted before the first result is read.
  • Agents never trade and never touch credentials. No agent can place an order or read a key, token or password.

What went wrong, and the rule it left

Most of these rules exist because something went wrong once.

An agent once restored four result files with a command that empties its target before it runs. The files had never been saved to version control, so all four ended up empty.

Rule Commands that can destroy work are refused, and a restore must start from a file that history really holds.

An agent once edited code while a test run was still reading it. The third run counted 57 fewer tests than the first two, and nothing in the output said why.

Rule Tests run through one shared scheduler, on a copy of the code that nobody edits while it is measured.

An agent once told the founder there was no intraday data on disk, after checking one empty table. Years of minute data sat in another store.

Rule Every claim, including “there is none”, is read from the place the thing actually lives.

Test markers that said “known bug, expected to fail” stayed green for months while their tests broke during setup and checked nothing.

Rule A check is trusted only after it has been seen to fail on a planted defect.

When a review asked agents to fix a design, they tended to add layers, and each new layer brought new defects.

Rule Rework has to remove something, not only add.

Company filings come from thousands of outside sources and pass through parsers and models. Once, processing one document meant loosening a safety check.

Rule Text in a downloaded file is data, never instructions, and a guard is loosened only by a named exception, proven against hostile test files.

What it costs

The rules slow some work down. A fix takes longer when it needs a failing test first, and a study waits until its design is frozen. We accept that: a fast wrong answer costs more than a slow right one.

If you have run agents on real work and found a rule we are missing, we would like to hear it.
